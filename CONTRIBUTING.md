# Contributing

Thanks for helping improve Compatibility Playbooks. Contributions should make an engineering review more evidence-driven, actionable, or clear while keeping the project Markdown-first and tool-neutral.

## Good contributions

- Improve a playbook's review coverage or output format.
- Add a realistic, fictional or safely sanitized example.
- Clarify a limitation, verification step, or deterministic check.
- Improve navigation, onboarding, or accessibility of the documentation.

## Before opening a pull request

- Search existing issues and playbooks to avoid duplicate work.
- Use fictional or sanitized examples. Do not include credentials, customer data, proprietary incident records, or confidential source code.
- Keep claims calibrated: distinguish observed evidence, assumptions, and unknowns.
- Keep the canonical workflows usable without a specific vendor or paid product.
- For a new or substantially changed workflow, include required inputs, a copy-ready prompt, output format, limitations, and a worked example.

## Pull request checklist

- [ ] The change addresses a concrete engineering review need.
- [ ] Links and examples are internally consistent.
- [ ] No secrets or restricted information are included.
- [ ] Tool-specific details are clearly optional and do not fragment the canonical workflow.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md). See [SECURITY.md](SECURITY.md) for reporting security concerns.
